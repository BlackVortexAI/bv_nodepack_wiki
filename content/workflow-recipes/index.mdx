## Publication rule

A recipe becomes verified only after dependency, load, wiring, execution,
output, persistence, PNG import, and extracted-JSON equivalence checks pass
against the documented release.

## Recipe catalog

| Recipe | Purpose | Primary dependency | Current gate |
| --- | --- | --- | --- |
| Regional V3 starter | Two named regions through the package-neutral conditioning path | Compatible base model | Draft |
| Model-specific Regional Attention | One isolated example per supported backend | Exact documented model architecture | Draft |

| Subgraph interface | Project structured controls into two Subgraph instances | Subgraph-capable ComfyUI frontend | Draft |
| Deterministic latent utilities | Fixed seed and constrained aspect-ratio behavior | Compatible sampling workflow | Draft |

Every recipe page must name its frozen settings, allowed exceptions, dependency
versions, expected output, and review owner. Follow [Workflow
Verification](/workflow-recipes/verification) before changing a recipe from
Draft to Verified.

## Publication artifacts

An approved downloadable recipe consists of matching workflow JSON and a
lossless PNG with embedded workflow metadata. A preview-only screenshot is not a
downloadable workflow. The two forms must be imported and compared independently.

Model-dependent visual quality requires explicit visual review. A structurally valid
workflow is not automatically an approved example result.
