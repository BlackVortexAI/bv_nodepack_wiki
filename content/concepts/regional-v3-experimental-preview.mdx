# Regional V3 Experimental Preview format

`BV_REGIONAL` V3 is a versioned, JSON-compatible context envelope. It contains a
strict core document and namespaced capabilities. Runtime objects such as models,
CLIP instances, images, latents, detectors, and LoRA stacks are not stored in it.

```json
{
  "schema": "bv.regional",
  "version": 3,
  "core": {
    "version": 1,
    "document_id": "uuid",
    "title": "Regional Prompt",
    "canvas": {},
    "prompts": {},
    "negative_mode": "auto",
    "overlap": {},
    "regions": []
  },
  "capabilities": {}
}
```

## Stability boundary

The namespaced data format is an Experimental Preview. Unknown capabilities are
transported unchanged, but there is currently no compatibility promise for the
Python registry lifecycle, frontend editor factories, resource registration, or
third-party panel integration. A stable public Extension Kit is deferred.

Envelope, core, and capability versions evolve independently. Capability keys use
the form `<pack-id>.<capability>`. Registered key collisions fail closed; import
order never silently replaces an interpreter.

## Graph and resource boundary

Runtime resources flow through ordinary persisted typed ComfyUI links. A context
stores serializable configuration and stable references only. Each external entry
stores both its `collector_id` and `resource_id`; resolution is restricted to the
same concrete graph.

V3 does not use prompt hooks, `graphToPrompt` patches, a persisted second registry,
global provider discovery, title matching, or slot-position fallback.

## Extension expectations

Future LUT, ControlNet, IPAdapter, image-editing, overlay, and similar features must
fit the existing envelope by registering a namespaced capability/resource type and
adding their specific configurator or executor nodes. They must not introduce a new
Regional socket type or merge two Regional contexts.

Do not publish third-party integrations as stable until the Extension Kit contract
is explicitly released.
