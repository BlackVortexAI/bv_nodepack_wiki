# Build a Regional V3 workflow

This guide builds a two-region workflow whose persisted ComfyUI links remain the
only graph truth. It covers the authoring node, an optional scoped LoRA capability,
and a compatible conditioning or attention consumer.

## Prerequisites

- BV NodePack from the V3 development branch;
- a model and matching BV conditioning/attention node;
- for external LoRAs, a compatible stack producer and one tested LoRA;
- all connected collectors and consumers in the same root graph or the same
  Subgraph definition.

Restart ComfyUI and hard-refresh the browser after updating BV NodePack.

## 1. Create the Regional document

1. Add **BV Regional Prompt**.
2. Select **Open Regional Editor**.
3. In **Document**, set the title and canvas dimensions.
4. In **Global**, enter instructions that apply to the whole image.
5. Add a region, give it a descriptive name, and draw its geometry.
6. Add a second region and repeat the process.
7. Set each region's usage to `generation`, `detailer`, or `both` according to
   the downstream consumer.

Region names are display labels. Runtime references use the persisted document
and region IDs, so renaming a region does not break its assignments.

## 2. Connect an executor

Connect `BV Regional Prompt.regional` to one compatible consumer, for example:

- **BV Regional Native Conditioning** for masked native conditioning;
- **BV Regional Anima Conditioning** for Anima;
- a supported BV model-specific Attention node;
- **BV Regional Detailer Plan** for ordered Detailer jobs.

Then connect the consumer's ordinary `MODEL`, `CLIP`, conditioning, image, or
sampler ports as required by that node. Repeating an executor intentionally
applies its behavior again; V3 does not maintain an execution-history registry.

## 3. Add an external Regional LoRA

1. Add **BV LoRA Stack Collector** and connect the external LoRA stack.
2. Open the LoRA capability editor on **BV Regional Prompt**, or add
   **BV Regional LoRA** downstream for a separate transformation step.
3. Add an entry and select both its collector and resource.
4. Select `Global` or a specific region as the target.
5. Choose the supported operation: Replace, Merge, Subtract, or Clear.

The Resource Picker creates an ordinary persisted typed ComfyUI link. The link
may be hidden visually, but it controls graph scope, execution order, caching,
copy/paste, and Subgraph behavior. Each external entry stores `collector_id` and
`resource_id` separately. Titles and slot positions are never used as fallback.

## 4. Save and verify

1. Save the workflow.
2. Reload it with a cache-busting hard refresh.
3. Reopen the editor and verify both region IDs and assignments remain resolved.
4. Change the live external stack and queue an uncached execution.
5. Confirm the downstream result changes and that unrelated region assignments
   remain unchanged.

## Typical errors

### Collector or resource is unresolved

Confirm the real provider link exists and both nodes belong to the same concrete
graph. Do not repair the selection by matching a node title. Select the intended
collector/resource explicitly.

### A copied consumer is unresolved

Copy the complete provider/consumer group, or reconnect the copied consumer to a
collector in its new graph. An isolated copy never searches other workflows or
Subgraphs.

### Legacy warning appears

An existing deprecated sidecar port is still connected. Existing execution stays
active, but the wiring must be migrated manually as described in the migration
guide.

## Removal or rollback

Disconnect the capability transformer or remove its scoped entries to return to
the upstream Regional context. Keep a saved workflow copy before replacing Legacy
wiring. Removing a collector without first updating its consumers deliberately
leaves visible unresolved references rather than silently retargeting them.
