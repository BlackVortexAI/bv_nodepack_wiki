## Choose a provider

Add **BV Remote LLM Provider** and choose a hosted or local
OpenAI-compatible profile. The shipped provider catalog defines the supported
profiles and their product defaults. Values selected on the node are serialized
as normal workflow widgets; credentials are not.

For a custom compatible service, use a profile that permits a custom endpoint.
Treat that endpoint as private infrastructure information when it contains an
internal host name, address, tenant, or routing identifier.

## Configure credentials

Use the node's **Configure API Key** action for profiles that require bearer
authentication. BV Node Pack stores keys separately from both the workflow and
the optional user-default settings. Deleting a configured key does not rewrite
workflow JSON.

The dialog shows the exact destination that will receive the key. Verify that
address before saving. Each key is bound to its profile and complete approved
endpoint, including scheme, host, port and path. A workflow cannot authorize a
different destination by changing its endpoint widget. To use a different
destination, open **Configure API Key**, verify the new address and enter the key
again. No existing key is prefilled or silently reassigned.

Existing keys for fixed catalog providers continue to use their catalog endpoint.
An older key for a custom provider has no destination approval and is blocked until
you save it again. Reading an old credential file does not rewrite it. Saving a key
upgrades the credential document while retaining other keys; unapproved custom
keys remain disabled until explicitly saved with a destination.

HTTP redirects are blocked, including redirects to the same host. Configure the
service's final Chat Completions URL directly. Removing or rebinding a key takes
effect on the next generation request, including requests with cached responses.

Local profiles such as Ollama, LM Studio, llama.cpp, vLLM, and LocalAI can use
their catalogued loopback endpoints without bearer authentication. Confirm the
selected local server and model are running before executing the workflow.

## User settings and secrets

BV Node Pack runtime state belongs below the active ComfyUI user directory:

```text
<ComfyUI user directory>/default/bv_nodepack/
  remote_llm_settings.json
  remote_llm_secrets.json
  cache/remote_llm/
```

`remote_llm_settings.json` is an optional advanced override document. It can
select a default provider profile and override only that profile's custom
endpoint, model, reasoning effort, and timeout. When the file is absent, the
provider catalog supplies the same defaults in memory; source checkout and Wiki
directories do not need a generated copy.

`remote_llm_secrets.json` is the separate credential store. Never copy it into
a workflow, repository, Wiki, issue attachment, or diagnostic archive. Do not
use a shared or broadly accessible ComfyUI user directory for credential
persistence; restrict access to the active user root. The response cache can
contain derived provider output and must be treated as user data as well.

Endpoint binding protects credential destinations. It does not authenticate the
ComfyUI server or its settings routes; keep access to the server restricted to
trusted users. Local providers without bearer authentication continue to work.

## Backup and troubleshooting

Back up settings only when preserving machine-specific defaults is intentional.
Store credential backups in an approved secret manager rather than beside
workflow files. Before sharing logs or configuration, remove API keys,
authorization headers, custom endpoints, local paths, prompts, and cached
responses.

If the provider node fails to load, validate the settings schema and profile ID
against the installed BV Node Pack version. Invalid or unknown overrides fail
closed; the runtime does not silently rewrite them.
