## Goal

Create a two-region 1024 × 1024 workflow, optionally assign independent LoRA
resources, and execute it through one compatible conditioning or attention node.

## Prerequisites

- BV Node Pack 1.3.0 or later;
- one compatible model and matching execution node;
- optional external LoRA stack producer and tested LoRAs;
- every provider and consumer inside the same owning workflow. Registered LoRA,
  LUT, and Detector Registry integrations can use managed provider routes across
  Root and Subgraph boundaries; manual and Legacy Collector chains must remain
  in the same concrete graph as their consumer.

## Build the document

1. Add **BV Regional Prompt** and open the Regional Editor.
2. Set the document to 1024 × 1024.
3. Author Global and Background prompts.
4. Add two named regions and draw their geometry.
5. Choose `generation`, `detailer`, or `both` usage deliberately.

## Add a consumer

Choose exactly one execution backend for the graph.

- **BV Regional Native Conditioning** consumes `regional` and a matching `CLIP`,
  then emits positive and negative conditioning for a standard sampler. It does
  not patch the model.
- A compatible model-specific Regional backend consumes the exact supported
  model architecture, `CLIP`, and Regional Context. Where applicable, connect
  both its patched model and its conditioning outputs to the sampler path.

Do not chain Native Conditioning and a model-specific backend for the same
Regional pass.

## Add scoped LoRA resources

1. Add **BV LoRA Registry** and configure one or more named stacks.
2. Open the Regional Prompt LoRA capability editor.
3. Select a Registry stack for Global or one region. The saved selection retains
   provider and resource identity plus its managed route inside the owning
   workflow.
4. Use `Replace`, `Merge`, `Subtract`, or `Clear` intentionally.

**BV Named LoRA Stack** → **BV LoRA Stack Collector** remains available as a
manual graph-local alternative. Keep that chain in the same concrete graph as
its consumer.

## Native Conditioning composition and quality

Native Conditioning is the generic masked-conditioning path. It is a practical
starting point, but it does not guarantee the strongest spatial fidelity or
image quality for every checkpoint and LoRA combination. Results also depend on
prompts, region overlap, LoRA compatibility and strength, and the selected
composition mode:

- `blend` uses the backward-compatible masked-conditioning layout;
- `exclusive` uses scope-specific masked branches without an additional
  unmasked conditioning branch;
- `hybrid` mixes both layouts. `hybrid_blend_ratio=0` matches `exclusive`, while
  `1` matches `blend`; and
- `mask_bounds` asks ComfyUI to use mask bounding areas. It requires a 2D image
  latent and is rejected for Anima.

The hybrid ratio affects only `hybrid`. Compare the modes with an unchanged
seed, checkpoint, LoRAs, prompts, sampler, and resolution. When an exactly
compatible model-specific backend exists, compare it separately: its
architecture-aware routing can be a better fit, but is not universally superior.

## Complete Native Conditioning example

The Selection Export prepared for this page uses Native Conditioning in
`exclusive` mode with an Illustrious-family checkpoint, Lazy Positive and Lazy
Negative embeddings, and separate Frieren and Fern LoRA Registry stacks. It is
a reproducible worked example, not a quality benchmark or a dependency-free
starter workflow.

Resources used by the example:

- [JANKU Trained Chenkin and NoobAI RouWei Illustrious XL — version 2786084](https://civitai.com/models/1277670/janku-trained-chenkin-and-noobai-rouwei-illustrious-xl?modelVersionId=2786084)
- [Lazy Positive embedding (`lazypos`)](https://civitai.com/models/1302719/lazy-embeddings-for-all-illustrious-noobai-pony-sdxl-models-lazypositive-lazynegative-positive-and-negative-plus-more)
- [Lazy Negative embedding (`lazyneg`), version 2121199](https://civitai.com/models/1302719/lazy-embeddings-for-all-illustrious-noobai-pony-sdxl-models-lazypositive-lazynegative-positive-and-negative-plus-more?modelVersionId=2121199)
- [Fern — 3 Outfits LoRA, version 1336553](https://civitai.com/models/1187364/fern-3-outfits-or-illustrious-or-sousou-no-frieren?modelVersionId=1336553)

## Verify

Save, reload, reopen the editor, change a live external stack, and queue an
uncached run. Confirm unrelated scopes remain unchanged.

## Save Civitai-compatible metadata

**BV Regional Image Save** keeps its `regional` input optional. Leave it
disconnected to retain the previous save behavior and metadata path.

When connected, use the same Regional Context that produced the image and keep the
node's `document_id` aligned with that context. The PNG then contains:

- raw Civitai/A1111-style `parameters` text with the combined Global, Background
  and enabled generation-region prompts;
- sampler, scheduler, steps, CFG, seed, size and denoise values when one supported
  sampler can be resolved upstream;
- the resolved base-model name and SHA-256 hash when the model file is available;
- materialized Regional V3 LoRAs and upstream core `LoraLoader` or
  `LoraLoaderModelOnly` resources, including strengths, scopes and hashes; and
- the complete versioned context in `bv_regional`, alongside ComfyUI's `prompt`
  and `workflow` chunks.

Metadata enrichment is fail-soft for file resolution and hashing: an unavailable
resource hash does not block image saving. A mismatched Regional Context and
`document_id` is rejected because silently attaching another document would make
the provenance misleading.

> Spatial conditioning guides a model. It does not guarantee anatomy,
> separation, interaction, or prompt compliance. Freeze a visually accepted
> seed per published workflow. Embedded workflow PNGs can expose prompts,
> settings, and model or LoRA filenames, so inspect their metadata before
> publication.
